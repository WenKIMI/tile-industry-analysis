# 证据库说明与首轮汇总

> 建立：2026-10-27　当前规模：4 份文档 / 23 条证据
> 用途：为季度报告提供可追溯的证据支撑，并作为 LLM 批量抽取的**验收基准**

---

## 一、文件命名与格式

```
data/evidence/
├── YYYY-MM-DD_来源_主题.json   ← 一份文档一个文件
└── 汇总.md                     ← 本文件
```

命名规则的作用：**"来源"字段可以直接用文件名**，避免抽取时来源串台。

每份 JSON 严格按 `prompts/01_evidence_extraction.md` 的 schema：

```json
{
  "来源": "文档标题",
  "日期": "YYYY-MM-DD",
  "链接": "原始 URL",
  "证据": [
    {
      "事实": "一句话陈述",
      "类型": "事实 | 观点 | 推断",
      "影响环节": "需求 | 供给 | 价格 | 成本 | 盈利 | 信用 | 政策",
      "传导到磨具": "磨边耗材 | 压机模具 | 无",
      "方向": "利多 | 利空 | 中性",
      "强度": "高 | 中 | 低",
      "可信度": "高 | 中 | 低",
      "原文摘录": "不超过 50 字的直接引用"
    }
  ],
  "矛盾点": ["..."],
  "缺失信息": ["..."]
}
```

**合并校验**：`py -3.13 src/merge_evidence.py`
会检查 JSON 可解析、字段齐全、枚举值合法，输出 `data/证据汇总.csv`。

## 三、从这轮统计里看出的三个问题（比证据本身重要）

### 问题 1：方向失衡 2:1，但可能不是行业真的那么差

利空 12 条、利多 6 条，2:1。脚本已经自动报警。

**但更可能的原因是取材偏误，不是行业真的一边倒**：我优先抓了"有硬数据"的文档——
出口（海关数据）、开窑率（产区走访）、成本（煤价）——这三类天然偏负面；
而偏正面的素材（政策解读、企业技改、新品发布）往往没有可引用的数字，被我跳过了。

**这说明一个方法论问题：有数据的新闻 ≠ 有代表性的新闻。**
数字多的题材容易被选中，而数字多的题材通常是"出问题"的题材。

### 问题 2：传导到磨具的证据只有 5/23，压机模具是 0

这是整个证据库最严重的结构缺陷。

**我关于磨具的判断，其实不是靠证据表支撑的，是靠评分卡的映射关系推出来的。**
证据表里几乎没有"磨具企业发生了什么"的一手材料——只有奔朗新材的财报数字（那在 `raw.csv`，不在证据表）。

**含义**：报告第 4 节「磨具映射」的说服力，目前弱于第 2 节「评分卡」。
如果要补，应该优先补：磨具企业的调研纪要、行业协会的磨具产销数据、下游客户访谈。

### 问题 3：信用环节 0 条

应收账款、账期、坏账——一条证据都没有。但这一项在评分卡里占 5% 权重，
得分来自三家财报的周转天数计算，**没有任何定性证据解释"为什么天数会降"**。

这正是红队自检里提到的"分母效应"问题——**没有证据，就只能靠推断**。

## 四、溯源三分校验记录

按 `prompts/01` 的要求，对这批证据做了三道校验：

| 校验 | 做法 | 结果 |
|---|---|---|
| ① 溯源 | 每条都回原文核对出处 | 通过。`原文摘录` 均为原文连续片段，未改写 |
| ② 查数 | 所有数字回原文核对 | 通过。出口量 4451.07 万㎡、煤价 825→902 元/吨、开窑率 7 成 / 不足 50% 等均已核对 |
| ③ 查类型 | 检查「观点」有没有被标成「事实」 | 通过。2 条观点（涨价难落地、停窑因亏本）已如实标注 |

**但要说清一件事**：这批证据是我（一个 LLM）抽的，不是人抽的。
三分校验由同一个模型自查，**只能发现"编造"，发现不了"选择性忽略"**。
上面列出的三个问题，就是自查查不出来、但靠统计能看出来的东西——

**这也说明为什么 `merge_evidence.py` 的统计报警比人工复核更有效。**

## 五、怎么用 LLM 批量复现（你之后要做的）

### 步骤

1. 下载文档 → 按 `日期_来源_主题` 命名
2. 复制 `prompts/01_evidence_extraction.md` 的系统提示词
3. **一次只喂一份文档**，贴进去，要求只输出 JSON
4. 存成 `data/evidence/<同名>.json`
5. 跑 `py -3.13 src/merge_evidence.py`
6. 看统计：字段有没有缺、方向是不是又失衡、传导到磨具的有没有增加

### 验收标准（拿本文件当基准）

LLM 输出满足以下四条才算合格：

- [ ] 每条证据都有 `原文摘录`，且能在原文里搜到
- [ ] 数字与原文一致（重点查这一项，幻觉数字最高发）
- [ ] `类型` 里没有把观点标成事实
- [ ] `矛盾点` 和 `缺失信息` 不为空（全空说明模型在敷衍）

### 一句话

**先跑 4 份、人工对一遍，再上批量。** 直接批量跑 50 份，错的地方你根本发现不了。
