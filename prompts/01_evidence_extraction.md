# 证据抽取 Prompt（核心）

用途：把政策文件、协会报告、财报、新闻，统一抽成可追溯的结构化证据表。
**只抽证据，不判断涨跌。** 方向由你的评分卡决定。

---

## 1. 系统提示词

```
你是行业研究助理，服务对象是一位做瓷砖行业景气分析的分析师。

你的唯一任务是「证据抽取」：从给定文本中提取与瓷砖行业景气相关的事实，
整理成结构化 JSON。你不判断行业好坏，不给投资建议，不预测涨跌。

绝对规则：
1. 区分「事实 / 观点 / 推断」三类，分类不确定时选更保守的那一类。
2. 每条证据必须带来源（文档标题或新闻标题）和日期；日期不明就写"未标注"。
3. 不确定的内容标「可信度=低」，不要猜。
4. 只抽取与瓷砖需求、供给、价格、成本、盈利、信用、政策相关的内容。
5. 每条证据标注是否传导到磨具：磨边耗材 / 压机模具 / 无。
6. 严禁编造任何数字。原文没有的数字，不要出现在输出里。
7. 原文未提及的内容，宁可留空，也不要补全。
```

---

## 2. 用户提示词模板

```
阅读以下文本，按 JSON schema 输出证据。

关注维度：需求 / 供给 / 价格 / 成本 / 盈利 / 信用 / 政策
传导对象：磨边耗材（跟产量走） / 压机模具（跟资本开支走） / 无

文本：
---
{document}
---
```

---

## 3. 输出 JSON Schema

```json
{
  "证据": [
    {
      "来源": "文件或新闻标题",
      "日期": "YYYY-MM-DD 或 未标注",
      "事实": "一句话陈述，只写原文支持的",
      "类型": "事实 | 观点 | 推断",
      "影响环节": "需求 | 供给 | 价格 | 成本 | 盈利 | 信用 | 政策",
      "传导到磨具": "磨边耗材 | 压机模具 | 无",
      "方向": "利多 | 利空 | 中性",
      "强度": "高 | 中 | 低",
      "可信度": "高 | 中 | 低",
      "原文摘录": "不超过 50 字的直接引用"
    }
  ],
  "矛盾点": ["与主叙事冲突的证据，一句话"],
  "缺失信息": ["要下判断还缺什么数据"]
}
```

---

## 4. 跑完之后必须做的三步校验

LLM 输出**不能直接信**，每次只花两分钟做这三件事：

| 步骤 | 做法 | 抓什么错 |
|---|---|---|
| ① 溯源 | 随机挑 3 条，回到原文找那句话 | 编造、张冠李戴、日期错位 |
| ② 查数 | 输出里每个数字，去原文核对 | 幻觉数字（最常见的坑） |
| ③ 查类型 | 看「类型」列，观点有没有被标成事实 | 把研报观点当客观数据 |

**任何一条溯源失败，整批输出作废重跑**，不要局部修补——局部修补会让你误以为模型整体可靠。

---

## 5. 常见问题与调法

| 现象 | 原因 | 怎么改 |
|---|---|---|
| 输出一堆「利多/利空」，没有事实 | 模型在替你下判断 | 强化"你不判断好坏"，把 `方向` 字段改成选填 |
| 数字对不上原文 | 幻觉 | 加一句"如果原文没有明确数字，写'未披露'"，并跑第 4 节校验 |
| 只抽到支持性证据 | 检索偏向 | 单独跑一次 `04_red_team.md` 的反方检查 |
| JSON 解析失败 | 输出混了说明文字 | 要求"只输出 JSON，不要任何前后缀"，或用 response_format |
| 同一事件重复多条 | 原文重复 | 加一句"同一事件只保留信息量最大的一条" |

---

## 6. 批量处理的建议

- **一份文档跑一次**，不要把十份文档塞进一个 prompt——证据会串台，来源对不上。
- 文件名统一 `日期_来源_主题`，例如 `2026-07-15_统计局_竣工面积月报.pdf`，这样"来源"字段可以直接用文件名。
- 抽完的证据表，按 `影响环节` 分组存 CSV，后面写报告时按环节检索。
